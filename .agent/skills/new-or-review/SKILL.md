# 写作与审稿

这个 skill 负责两类任务：

- 新建文章，从题目和材料推进到可审阅的初稿
- 审阅已有文章，检查事实、结构、证据、表达和材料边界

## 基本原则

- 材料不足时先询问，不用常识补造经历、数据或判断
- 文章结构服务于问题和证据，不套固定模板
- 技术文章优先保留命令、日志、benchmark、代码和具体数字
- 审稿建议要能落到句子、段落或证据位置
- 改写只处理当前问题，不整篇重写
- `review_signals.py` 只提供线索，不替代事实核验和人工判断

## 目录

- `references/new-post-workflow.md`：从题目到初稿的阶段流程
- `references/review-and-revise.md`：审阅、修订和停止条件
- `references/article-types.md`：常见文章类型的结构提示
- `references/style-extraction-method.md`：分析用户提供样本的通用方法
- `scripts/review_signals.py`：段落级信号扫描脚本

## 新建文章

1. 明确读者、问题、范围和交付形式
2. 收集作者已有的场景、材料、判断和证据
3. 选择文章类型，列出可验证的提纲
4. 标记事实缺口和不确定判断，先向作者确认
5. 写出初稿，保留问题推进和证据来路
6. 运行审阅流程，只修改已经确认的问题

## 审阅文章

1. 先读全文，概括文章真正回答的问题
2. 检查事实、数字、引用、代码和因果关系
3. 检查结构是否由问题和证据推动
4. 检查是否存在模板化表达、空洞总结和过度平滑
5. 对每个问题给出位置、原因和最小修改方向
6. 缺少作者材料时列出问题，停止继续补写

## 风格样本

只有用户提供样本并明确要求分析或模仿时，才读取 `references/style-extraction-method.md`。只提取可观察的结构、证据组织和句法动作，不复制身份、经历、口头禅或未经授权的个人风格。

## 程序化审阅

```bash
python .agent/skills/new-or-review/scripts/review_signals.py path/to/article.md
```

输出是审阅线索。命中不代表必须修改，未命中也不代表文章没有问题。
